> 広大なマップに点在する集落を、交通network（道路・鉄道）で繋いで育て、都市へと発展させていく、単色ミニマル3Dの育成型トランジットゲーム。

**最終更新：** 2026-07-24
**バージョン：** v2（「点在集落network」モデルへ大改訂）

## 0. v1からv2への転換（最重要）

**v1の想定：** 中心に大きな街が1つ、外側は空地。→ 駅を街の中に置くだけで、「繋ぐ」判断が生まれず、ゲームとして活用しづらかった。

**v2の想定：** マップ全体に集落が**距離を置いて点在**。それを交通で**繋いで育てる**。

この転換で「どの集落とどの集落を繋ぐか」という**トランジットゲームの核**が生まれる。街は1つの塊ではなく、点と点を線で結んで広げていくもの。

### マップは時間とともに変化する ★
マップは静止した盤面ではなく、ゲーム進行に伴って**育って変化していく**のが本質。以下は同じマップの一角が、序盤→中盤→終盤でどう変わるかのイメージ。

```
【序盤】疎らに集落が点在。多くは空地。まだ何も繋がっていない
空地 | 集落 | 空地 | 空地 | 集落
空地 | 空地 | 空地 | 集落 | 空地
空地 | 集落 | 空地 | 空地 | 空地

        ↓ 幹線道路で集落を繋ぐ・時間経過で集落が増える

【中盤】道路で繋がった集落が町へ育つ。間の空地にも人が住み着き始める
集落 | 町  | 集落 | 集落 | 町
空地 | 集落 | 集落 | 町  | 集落
集落 | 町  | 空地 | 集落 | 集落

        ↓ 町が密集して都市化・都市間を鉄道で結ぶ

【終盤】町が密集したエリアが都市・大都市に。都市間を鉄道が貫く
町  | 都市 | 都市 | 町  | 都市
集落 | 都市 |大都市| 都市 | 町
町  | 都市 | 集落 | 都市 | 都市
```

- **重要な但し書き：** 実際は人口が**連続的に増えていくグラデーション**であり、「集落」「町」「都市」は段階がくっきり切り替わるわけではない。あくまで**人間が状態を理解するための便宜的なラベル**。見た目も色と高さの連続変化で表現し、離散的な"進化演出"にはしない。

## 1. コンセプト

広いマップに、人口を持つ集落が疎らに点在している。プレイヤーは道路・鉄道で集落どうしを繋ぐ。繋がれた場所は交通の恩恵を受けて発展し、間の空地にも人が住み着いて新たな集落が生まれる。集落は町へ、町が密集すると都市へと育ち、育った都市どうしを今度は鉄道で結んでいく。

**一言でいうと：** 「Mini Metro の抽象美 × 点在する街を繋いで育てる喜び」。生存パズルではなく、開拓・成長シミュレーション。

---

## 2. マップとセルの概念 ★v2の土台

- マップは**セル（グリッドのマス）**で構成される。各セルが状態（主に**人口**）を持つ。
- セルの人口が交通の恩恵で増えると、そのセルが発展段階を上がっていく。
- **セル = シミュレーションの基本単位**。実装上も各セルが値を持つので計算しやすい。
- **初期配置はランダム生成**（箱庭・リプレイ性重視）。毎回違うマップを開拓する。
  - 生成ルール要件：「疎らに集落が散り、空地も適度にある」バランス。全部空地でも集落だらけでもダメ。

---

## 3. 発展段階モデル ★v2の核

セルは交通の恩恵と人口に応じて、段階的に成長する。

```
空地（無人）
  ↓ 交通網が繋がって恩恵を受ける／時間経過
集落（小さな人口）
  ↓ さらに恩恵・人口増
町（中規模）
  ↓ 町がいくつも密集して囲まれる
都市（大規模・高層）
  ↓ 都市が発展・集積する
大都市（最大規模・超高層）
```

- **段階は連続的、名前は便宜上 ★：** 人口は連続値で増えていく。上記5段階（空地/集落/町/都市/大都市）は、状態を人間が理解するための**ラベル**にすぎず、くっきり切り替わるわけではない。したがって「レベルアップ！」的な離散演出はせず、**色と高さがなめらかに変化していく**形で表現する。
- **見た目での表現**：発展段階は**セルの色と建物の高さ**だけで表す（抽象度を保つ）。集落＝低く疎ら、大都市＝超高層で密集。
- **駅は人を呼ぶ**：需要をさばくだけでなく、**需要を生み出す**。人口の少ないセルに駅を置くと、そこに人が住み着いて集落が形成される。空地の開拓手段になる。

### 成長のきっかけ（3つの蛇口）★
空地・集落が育つトリガーは3種類。成長ドライバーが複数あることでバランスが取れる。

| きっかけ | 性質 | 効果の大きさ |
|---|---|---|
| 駅・施設を置く | 能動（プレイヤーの戦略の主役） | **大**（狙った拠点をブースト） |
| 道路で繋ぐ | 受動（繋いだ場所がじわじわ育つ） | 中 |
| 時間経過でランダム | 自発（放置でも世界が少し動く） | **小**（スパイス程度） |

- **序列：** 駅 ＞ 道路 ＞ 自発ランダム。
- 自発ランダムは「新しい集落が勝手に生まれる → プレイヤーが繋ぎたくなる」という反応を誘発する役割（Mini Metro の駅増加に相当）。強すぎると放置ゲーになるので弱めに。→ チューニング事項。

## 4. コアループ

```
点在する集落を道路・鉄道で繋ぐ
      ↓
交通の恩恵でセルが発展（空地→集落→町→都市）  ←─ 正のフィードバック（開拓の快感）
      ↓
人口が増え、需要も増える
      ↓
インフラが追いつかないと渋滞           ←─ 負のフィードバック（停滞の緊張）
      ↓
プレイヤーが投資判断（道路増設／鉄道敷設）を迫られる
      ↓
育った都市どうしを鉄道で結び、さらに広域化
      ↓
（ループに戻る）
```

- **主軸 = 育成／開拓**：街を繋いで広げる喜びが土台。負けで終わらせない。
- **緊張のスパイス = 渋滞**：詰まると「崩壊」ではなく「停滞」。鉄道投資を促す。
- **区切り = ゆるい目標**（論点3・未確定）：例「全集落を町以上に」「N個の都市を鉄道で繋ぐ」など。箱庭方向なので緩めに。プロトタイプで詰める。

## 5. インフラ 3層構造 ＋ スケールでの使い分け

毛細血管 → 動脈 → 大動脈。v2では**発展スケールごとに使う道具が変わる**のがポイント。

### ① ローカル道路（最下層・自動生成）
- 人が住み着いたセルには必ず現れる格子状の基盤インフラ＝地面のグリッド。
- プレイヤーは設置しない。無彩色・控えめ。駅の吸着基準にもなる。
- 街のあるセルにだけ存在（無人セルには無い）。

### ② 幹線道路（プレイヤーが引く・低コスト・中容量）
- **集落を繋ぐ主力**。安く柔軟に敷ける（低費用がゲーム的な狙い）。
- 容量が低く超えると渋滞。需要削減は限定的。
- **影響の形は「線」**：一点ではなく、道路の**線全体から均等に、帯状（バッファ状）に**、やや弱く恩恵が広がる。
- 沿線のセルは発展する（鉄道沿いより控えめ、= 集落〜町くらいまで）。
- 見た目：グレー系（鉄道の色は使わない）。ローカル道路より明確に太く。
- **将来拡張：** 高速道路など、より上位の道路インフラを後で追加検討（今は保留）。

### ③ 鉄道路線（プレイヤーが引く・高コスト・大容量・主役）
- **育った都市どうしを結ぶ**大動脈。設置コスト高・大容量。
- **影響の形は「点」**：駅を中心に放射状（円状）に強く恩恵が広がる。
- 沿線・駅周辺は最も発展する（都市化）。
- 見た目：鮮やかな色。**描画順を建物より優先**（隠れない）。**路線ごとに色分け**（Mini Metro式、1路線目=青）。曲がり角は緩いカーブでなめらかに。

### 設置ロジック（プレイヤーの思考順）
```
基本はローカル道路グリッドで賄う
  ↓ 集落を繋ぎたい／足りない
幹線道路を敷く（低コストで面を繋ぐ）
  ↓ 人口密度が高い都市ができた
駅＋鉄道で都市間を結ぶ（拠点を高速大容量で連結）
```
→ 駅は密集地（都市）にポツポツ。**駅間は広く開ける。**

## 6. 交通充足度スケール（地面の色）

各セルの「交通が足りているか」を、地面を染める**1本の連続スケール**で表現。円で囲わず面のグラデーションにする。

```
濃い赤 ← オレンジ ← 白 → 青 → 明るい緑
困窮      不便    普通  やや充足  充分カバー
```

- **充足の序列：** 鉄道（緑・強）＞ 幹線道路（青・弱）＞ 無インフラ（白）。
- 影響の合成：複数の駅・道路の恩恵は同じ「充足度」に足し込まれる。駅と駅の間は特に緑。
- **困窮（赤）の限定ルール ★更新：** 赤で染めるのは「**建物が立っているのに、駅・幹線道路のどちらからも恩恵を受けられていないセル**」に限定する。マップ外周全体を一律に赤くしない。該当する建物を中心に、薄く赤を塗る。
  - 未開拓の純粋な空地は無色（グレー）。「困窮」は"人がいるのに交通が届かない"状態のことであって、"ただの空地"ではない。
- **表示はモード依存**：充足度の色は編集モードでのみ表示。鑑賞モードでは消す。

## 7. 操作・カメラ ★重要な設計軸

### スマホ前提のシンプル操作
- 指2アクション基本：**タップで駅設置／ドラッグで路線を引く**。
- 情報は数字でなく**色とアニメーション**で伝える。
- カメラは**自由回転させない**。用意された「良い画」を切り替える方式。

### 2モード制（カメラ＋表示情報の両方を切り替える）
| | 編集モード | 鑑賞モード |
|---|---|---|
| カメラ | 俯瞰（マップ全体を見渡せる引き） | 横〜低いアングル |
| 目的 | 開拓の「作業画面」 | 育った街を「愛でる画面」 |
| 表示情報 | 全部出す：充足度の色、グリッド、路線強調、カバー | 情報レイヤーを消し、純粋に街だけ |
| 許容 | ゴチャついてOK | 徹底的にクリーン |

- **v2での追記：** 点在する集落を扱うため、編集モードは**マップ全体を見渡せるズームアウト**が要る。ピンチズームでマップ全体〜拠点を行き来。
- モード切り替えのインタラクション実装は Unity 本実装フェーズで（プロトタイプは静止で見た目を固める）。

### プレイ範囲の拡大：マップ拡張型（A案）★確定
Mini Metro のように、**序盤は狭い範囲、進行に伴って徐々に広い範囲へ**とプレイ空間が広がっていく。「世界が広がっていく」感覚＝成長の実感そのもの。

- **方式は「マップ拡張型」：** マップは最初小さく、進行すると**マップの端が広がって新エリアが出現する**（＝新しい土地が増える）。
  - ※対案だった「マップは最初から広大で視界だけ広がる（視界拡張型）」は不採用。世界そのものが拡張していく方を採る。
- **序盤：** 小さな範囲に少数の集落。ここでルールに慣れる。
- **中盤以降：** マップが拡張し、遠くの町・新しい集落まで含む広い範囲を経営する。
- **新エリア出現時の生成：** 拡張されるたびに新しいエリア（集落・空地）をランダム生成する必要がある。→ ランダム生成ロジックは「初期マップ生成」だけでなく「拡張時の追加生成」も担う（実装メモ参照）。
- **拡張のきっかけ（論点・未確定）：** マイルストーン達成で解放（人口N到達→新エリア）／時間経過で自動、などが候補。前述の「ゆるい目標で牽引」と繋げると綺麗（目標達成のご褒美＝新しい土地）。この方向で検討中。
- **スマホ操作上の注意：** 序盤（狭い）と終盤（広い）でカメラの引き幅が大きく変わる。ズームしても指の操作感（タップ精度・ドラッグのしやすさ）が破綻しないよう要調整。

## 8. ビジュアル方針

- **単色ミニマル3D**。白〜ライトグレー基調、クリーンで昼っぽいトーン。
- **抽象都市**：ビルは均質な四角いボックスの群れ。モダニズム建築の美学。
- **高さ = 発展度**：都市＝高層で密集、集落＝低く疎ら、空地＝無し。
- **質感が命**：柔らかいソフトシャドウ、AO、影は寒色（青み）寄り。
- **色は情報**：無彩色ベース。色は意味を持つ要素だけ（充足度スケール／路線色）。
- **駅**：地面から立ち上がる立体マーカー（ピン/柱）。描画順優先で建物に隠れない。
- **抽象度の歯止め ★：** v2は Cities:Skylines / A列車 方向に一歩近づく。集落・町・都市の段階も**セルの色と高さだけ**で表現し、複雑なシミュに操作を引っ張られないよう厳守する。スマホで指2アクションを守る。

**Claude Design 設定：** Design system = Modernist。

## 10. 実装メモ（アーキテクチャ）

> ※実装フェーズの覚書。Claude Design プロトタイプとは別レイヤー。想定ターゲット：Unity（C#）。

- **シミュレーションコアとプレゼンテーション層を分離**（既存の設計思想を踏襲）。
  - シムコア：セルの人口・発展段階・交通充足度・渋滞の計算。
  - プレゼン層：ボックス描画、地面の色、カメラ。
- **セルベースのシミュレーション**：各セルが人口等の状態を持つ。発展段階の遷移もセル単位。
- **交通充足度マップはリアルタイム計算不要**：駅・道路を設置／変更した時だけ再計算。
  - → 重い影響度伝播計算を**バックグラウンドスレッド**に逃がせる。メインは描画・操作に専念。
  - → コアとプレゼンの分離があるからマルチスレッド化しやすい。
- **時間経過の自発成長**は低頻度のティックで処理（毎フレーム不要）。
- **マップ拡張（A案）**：初期マップ生成に加え、拡張時に新エリアのセル群を追加生成する処理が要る。既存マップの端に自然に繋がるよう生成する（境界の整合性）。拡張はイベント発火時のみ（毎フレーム不要）。
- **描画負荷対策**：ボックスは大量に出る前提。**GPUインスタンシング**。マップが広くなるほど重要。育ったビルのまとめ、視界外カリング等も検討。
- プロトタイプは Claude Design（three.js）で見た目を固め、Claude Code へハンドオフして Unity 本実装へ繋ぐ。

## 11. 制作進捗

段階を刻んで積み上げる。**下の層から固める／動きも要素も1個ずつ。**

### v1で完了（1つの街モデル・資産として流用可能）
- [x] 質感・器（白基調・俯瞰・四角ボックス・寒色影・AO）
- [x] 静的要素（駅・鉄道・グリッド・駅中心の発展・建物の状態）
- [x] 交通充足度スケール（赤〜白〜青〜緑の面グラデ）の基礎
- [x] 幹線道路の充足度反映・存在感（調整中）

### v2でやること（点在集落モデルへ作り直し）
- [ ] **序盤の小さいマップ＋点在する集落**の初期状態を生成・表示（マップ拡張型なので序盤は狭く）
- [ ] セルの発展段階（空地/集落/町/都市/大都市）を色と高さで表現（連続的に）
- [ ] （後）マップ拡張の仕組み（進行で端が広がり新エリアが出現）
- [ ] 困窮（赤）を「人がいるのに無インフラなセル」に限定
- [ ] 幹線道路＝線バッファ／駅＝点放射、の影響の形の違いを表現
- [ ] （その後）駅・道路を敷く → セルが発展する動き（ステップ③相当）
- [ ] （その後）成長が伝播していくデモループ（ステップ④相当）
